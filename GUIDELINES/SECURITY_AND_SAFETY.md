# ElectEd India – Security & Safety Guidelines

This document defines the **security and safety constraints** governing the design and behavior of **ElectEd India**.

Security and safety are treated as **foundational design principles**, not post‑implementation checks. All application logic, AI behavior, and UI affordances must comply with these guidelines.

These guidelines apply to:
- Application flow and user interaction
- AI behavior (Gemini)
- UI generated by Google Antigravity
- Data handling and usage decisions

---

## 1. Security-by-Design Principle

ElectEd India is designed as an **educational-only system** with a deliberately constrained surface area.

To minimize risk:
- No personal data is collected
- No official actions are performed
- No implicit trust is placed in user input
- All AI responses are tightly scoped and grounded

Reducing system capability is a conscious security choice.

---

## 2. Input Safety and Intent Control

All user input must be treated as **untrusted**.

Before any response is generated:
1. User input must pass through intent classification
2. The intent must be verified as **in-scope**
3. Out-of-scope input must be refused deterministically

This prevents:
- Prompt injection attempts
- Circumvention of scope boundaries
- Unsafe or speculative responses

No user input may directly reach answer generation without classification.

---

## 3. Hallucination and Misinformation Prevention

ElectEd India operates under a **closed-world assumption**.

- The AI model may generate answers **only** from explicitly allowed grounding sources
- External knowledge, inference, or memory-based reasoning is prohibited
- Missing or unverifiable information must result in refusal

This constraint is enforced to prevent:
- Misinformation
- Hallucinated guidance
- Incorrect civic or procedural advice

---

## 4. Personal Data Protection

ElectEd India must never:
- Request personal information
- Accept identity-related inputs
- Process EPIC numbers, phone numbers, addresses, or identifiers

The UI must not:
- Encourage data entry
- Suggest identity verification
- Imply user-specific results

All official actions must occur only on official Election Commission of India portals.

This eliminates risks related to:
- Privacy breaches
- Identity misuse
- Data storage liability

---

## 5. Transaction and Action Isolation

ElectEd India must remain **non-operational**.

The system must not:
- Perform registrations
- Modify voter records
- Check application or voter status
- Submit forms or requests

The application explains processes but does not participate in them.

This isolation prevents:
- Unauthorized transactions
- Misrepresentation as an official system
- Accidental misuse by users

---

## 6. Political Neutrality and Abuse Prevention

ElectEd India must remain strictly neutral.

The system must not:
- Express political opinions
- Compare parties or candidates
- Predict outcomes or trends
- Reinforce persuasive narratives

All such queries must be identified and refused.

This protects:
- Democratic neutrality
- System integrity
- User trust

---

## 7. Model Code of Conduct Safety Boundaries

The Model Code of Conduct (MCC) is handled strictly as an **awareness topic**.

ElectEd India may explain:
- What the MCC is
- When it applies
- Why it exists

ElectEd India must not:
- Interpret violations
- Advise on enforcement
- Suggest compliance strategies

This avoids providing legal or quasi-legal guidance.

---

## 8. Deterministic Refusal Behavior

When a request is:
- Out of scope, OR
- Unsafe, OR
- Unverifiable from allowed sources,

ElectEd India must respond **only** with the predefined refusal message:

> “This information is not available in official Election Commission of India sources.”

The refusal response must:
- Not be softened
- Not be elaborated
- Not include alternatives or speculation

Consistent refusal behavior is a security feature.

---

## 9. UI-Level Safety Constraints (Antigravity Guidance)

When generating the UI, the following must be enforced:

- No fields for personal data
- No action-oriented buttons (e.g., “Apply”, “Check status”)
- No suggestion of official authority
- Clear educational framing

The UI must reflect **capability boundaries**, not invite exploration beyond them.

---

## 10. Disclaimer Enforcement

The following disclaimer must always be present in the application:

> *ElectEd India is an educational tool and is not affiliated with the Election Commission of India.*

This ensures clarity of intent and prevents misinterpretation of authority.

---

## 11. Security Scope Summary

ElectEd India prioritizes security through:
- Minimal capability
- Explicit constraints
- Deterministic behavior
- Clear refusal rules
- Strong grounding discipline

Security is achieved by **design simplicity**, not by complex enforcement mechanisms.
