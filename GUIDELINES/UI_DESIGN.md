# ElectEd India – UI Design Specification (MVP)

This document defines the **visual and interaction design** for the **Ask ElectEd**
feature of ElectEd India.

The UI is intentionally **conversation‑first**, minimal, accessible, and trust‑oriented.
It must be generated by Google Antigravity strictly according to the principles and
constraints defined here.

All UI decisions must comply with:
- `GUIDELINES/FEATURES.md`
- `GUIDELINES/SECURITY_AND_SAFETY.md`
- `GUIDELINES/ACCESSIBILITY.md`

---

## Antigravity UI Design Principles (Mandatory)

When generating the ElectEd India UI, the Antigravity Agent must follow these
explicit principles. These principles are **binding** and override default
UI generation behaviour.

### 1. Conversation‑First, Not App‑First
- Treat the conversation itself as the primary interface
- Avoid dashboards, cards, or navigation‑heavy layouts
- The UI should feel similar in interaction flow to modern AI chat interfaces

### 2. Single‑Column, Low‑Chrome Layout
- Use a single‑column conversational layout
- Minimise headers, borders, cards, and decorative containers
- Keep visual focus on message exchange, not UI components

### 3. Search‑Inspired Simplicity
- Design the input experience like a trusted search interface:
  - One clear input
  - One primary action
- Avoid suggestion grids, menus, or exploratory UI elements unless explicitly required

### 4. Accessibility Overrides Aesthetics
- Accessibility requirements take precedence over visual creativity
- Prefer clarity, contrast, and readability over decorative styling
- Avoid animations or transitions that increase cognitive load

### 5. Predictability Over Delight
- Do not introduce playful, expressive, or whimsical UI elements
- Maintain consistent styling for:
  - Normal answers
  - Refusals
- The UI should feel calm, educational, and neutral

### 6. No Implied Authority
- Do not style the UI to look official or governmental
- Avoid seals, insignia, or institutional symbolism
- Reinforce the educational (non‑affiliated) nature of the app

---

## Responsive and Cross‑Device Design (Mandatory)

The ElectEd India UI must be **fully responsive by design** and accessible
from the browser on:

- Mobile phones
- Tablets
- Laptops and desktop computers

Antigravity must ensure that:

- The layout adapts cleanly to different screen sizes and orientations
- The conversational interface remains usable on small screens
- Text remains readable without horizontal scrolling
- Input areas and buttons are touch‑friendly on mobile devices
- No functionality is limited to a specific device class

Responsive behaviour is a **core UI requirement**, not an enhancement.
The UI must support equal access to civic education regardless of device.

## Reference Design Inspirations (For Antigravity)

When generating the UI, Antigravity must explicitly draw **design inspiration**
from the following successful products and design approaches, adapting their
best practices rather than copying visual assets:

- **ChatGPT (Web UI)**
  - Single‑column conversational layout
  - Clear separation of user and assistant messages
  - Minimal visual chrome with focus on dialogue

- **Google Conversational Interfaces (Search & Assistant design)**
  - Search‑like simplicity
  - Input primacy and low friction
  - Neutral, high‑trust visual language

- **Modern accessibility‑first AI chat applications**
  - Readable typography and spacing
  - Scannable responses
  - Predictable and consistent behaviour

These references are **design anchors**, not templates.

## Overall Design Philosophy

The UI is built around a single guiding idea:

> **Conversation is the interface.**

There are no dashboards, menus, or workflows. Users interact solely through
natural‑language questions and answers, receiving value immediately without
learning navigation patterns.

---

## Layout Structure

### Single‑Column Conversational Layout
- Centre‑aligned, single column
- Messages flow chronologically from top to bottom
- Input area remains anchored at the bottom

This structure minimises cognitive load and mirrors the most successful
conversational AI products.

---

## Header Area

### Purpose
Establish trust and context without distraction.

### Elements
- **App Name:** ElectEd India
- **Tagline (subtle):** *Your Guide to the Indian Election Process*

The header must remain visually restrained so attention stays on the conversation.

---

## Conversation Area

### Message Presentation
- User messages are right‑aligned
- ElectEd responses are left‑aligned
- Visual distinction relies on alignment, spacing, and typography
- Colour is never the sole differentiator

### Response Formatting
ElectEd responses must:
- Use short paragraphs
- Prefer bullet points where helpful
- Avoid dense text blocks
- Maintain a calm, neutral, educational tone

---

## Conversational Continuity

The UI must support **multi‑turn conversation with context**:

- Previous messages remain visible
- Follow‑up questions may refer to earlier answers
- The conversation flows naturally without resets

Context is session‑scoped and non‑personal. There is no long‑term memory.

---

## Input Area (Ask Zone)

### Placement
- Fixed at the bottom of the screen
- Always visible and keyboard accessible

### Design
- Large, single‑line input field
- Placeholder text:
  **“Ask a question about the Indian election process…”**
- One primary action button: **Ask**

No secondary actions, no menus, no shortcuts.

---

## Colour Scheme

### Recommended Palette
- Background: Off‑white or very light neutral grey
- Primary text: Near‑black (high contrast)
- Accent colour: Deep blue or neutral institutional tone

Colours must signal trust and seriousness, without political or authority cues.

---

## Refusal Response Design

When a question is out of scope or unverifiable, the response must appear in the
same conversational flow using **exactly** the following text:

> **“This information is not available in official Election Commission of India sources.”**

The refusal:
- Uses the same typography as normal answers
- Is not styled as an error
- Includes no explanation or alternatives

---

## Accessibility‑Driven Design (UI‑Visible)

The UI must visibly support accessibility:
- Full keyboard navigation
- Clear focus indicators
- High‑contrast text
- No colour‑only status indicators
- Minimal motion and animation
- One task per screen

Accessibility is a core requirement, not an enhancement.

---

## Footer / Trust Signal

A small, persistent footer must be present:

*ElectEd India is an educational tool and is not affiliated with the Election
Commission of India.*

---

## Elements Explicitly Disallowed in UI

The UI must not include:
- Personal data fields
- Voter ID, EPIC, age, or location inputs
- Transactional buttons (Register, Apply, Check Status)
- Political imagery or party references
- Dashboards or multi‑panel layouts

---

## UI Design Summary

Antigravity must generate a UI that:
- Feels familiar to users of modern AI chat interfaces
- Is calm, readable, and neutral
- Makes conversation the sole interaction paradigm
- Reflects safety, accessibility, and civic responsibility by design
