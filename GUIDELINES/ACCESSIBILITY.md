# ElectEd India – Accessibility Guidelines

This document defines the **accessibility and inclusive design constraints**
governing the user experience of **ElectEd India**.

Accessibility is treated as a **core design requirement**, not an enhancement.
All UI generated by Google Antigravity and all user interactions must comply
with these guidelines.

These guidelines apply to:
- UI structure and layout
- Interaction patterns
- Content presentation
- Conversational interface behaviors

---

## 1. Accessibility-First Design Principle

ElectEd India is designed for **broad public use**, including:
- First‑time voters
- Users with visual, motor, or cognitive impairments
- Users on low‑end devices or assistive technologies

Accessibility is a **default requirement**, not an optional mode.

Accessibility considerations include full keyboard navigation, high-contrast design, non-color-only indicators, clear plain-language messaging, and minimal cognitive load.

---

## 2. Perceivable Content

All information must be perceivable without reliance on a single sense.

The UI must:
- Use sufficient color contrast between text and background
- Avoid conveying meaning through color alone
- Ensure text is readable at various screen sizes and zoom levels
- Present clear visual hierarchy using headings and spacing

Conversational responses must:
- Avoid dense paragraphs
- Prefer short sentences and clear structure
- Use bullet points where helpful for readability

---

## 3. Operable Interface

All interactions must be operable using multiple input methods.

The UI should:
- Be fully usable with a keyboard
- Avoid time‑limited interactions
- Provide visible focus states for interactive elements
- Ensure buttons and click targets are adequately sized

The conversational interface must:
- Allow users to submit questions without complex gestures
- Avoid interaction patterns that require precision or speed

---

## 4. Understandable Language and Interaction

ElectEd India must prioritize clarity and simplicity.

All UI text and responses must:
- Use plain, non‑technical language
- Avoid legal, bureaucratic, or procedural jargon
- Present information in a predictable and consistent manner
- Avoid sudden changes in context or behavior

The conversational agent must:
- Answer in a calm, neutral tone
- Avoid ambiguity
- Clearly refuse out‑of‑scope requests using a consistent message

---

## 5. Robust Interaction with Assistive Technologies

The UI must remain compatible with assistive technologies such as:
- Screen readers
- Keyboard navigation tools
- Voice interaction systems

To support this:
- Structural elements should be clear and well differentiated
- Dynamic content updates should not disrupt context
- Interactive elements must be labeled clearly

---

## 6. Accessibility in Conversational Experience

The **Ask ElectEd** feature must support inclusive conversation:

- Users should not be required to phrase questions “correctly”
- Free‑form input should be accepted without strict formatting
- Error states and refusals must be understandable and non‑punitive
- The refusal message must remain simple and consistent

Accessibility includes cognitive accessibility, not just visual or motor access.

---

## 7. Avoidance of Accessibility Barriers

The UI must avoid:
- Flashing or rapidly changing elements
- Overly dense text blocks
- Excessive animations
- Multi‑step interactions for simple actions

Simplicity is an accessibility feature.

---

## 8. Antigravity-Specific Guidance

When generating the UI, Google Antigravity must:

- Favor simple layouts over complex visual structures
- Ensure conversational input and output are easy to locate
- Maintain consistent spacing and alignment
- Use accessible defaults rather than custom styling
- Reflect educational intent clearly in the design

Accessibility constraints override aesthetic preferences.

---

## 9. Accessibility Scope Summary

ElectEd India achieves accessibility by:
- Designing for clarity and simplicity
- Supporting diverse interaction methods
- Using predictable and readable conversational responses
- Avoiding unnecessary complexity in UI and flow

The goal is **inclusive civic education for all users**, regardless of ability.
